# zabbix-sla-tools

Скрипты к Zabbix 7.4 API, с помощью которых я построил SLA-отчётность для руководства. Внутри три дерева сервисов (интернет, безопасность, бизнес-сервисы) и 11 SLA, а дашборд читается без знания Zabbix.

## Как устроены SLA

- **Два уровня на каждую область: SLO 95 и SLO 99.** Zabbix не умеет задавать целевой диапазон, поэтому пара SLA показывает три состояния: «ниже 95», «95–99» и «выше 99».
- **Рабочие часы.** Интернет, VPN и Wi-Fi считаются только с 07:00 до 21:00 МСК (SLA `schedule`). Ночные работы не портят месячный отчёт.
- **Пропорциональный SLA интернета.** Вместо «работает / не работает» считается произведение компонентов: `100 × интернет × NetBird × внешний VPN × доля онлайн-точек Wi-Fi`. Если упала половина точек доступа, отчёт показывает 50%, а не 0% и не 100%.
- **Видеонаблюдение как среднее, а не аптайм.** SLA камер равен среднему проценту работающих камер за месяц по всем NVR-серверам (`trendsum/trendcount`).

## Скрипты

| Файл | Что делает |
| --- | --- |
| `vpn-external-trigger.py` | Заменяет одноразовый шаблонный триггер на триггер «3 неудачные проверки подряд или нет данных 5 минут» только на одном хосте. Шаблон, общий для других хостов, не меняется. Убрал ложные аварии VPN из-за разового HTTP 404 от проверяемого сайта. |
| `internet-proportional.py` | Восстанавливает историю пропорционального SLA с начала месяца по трендам и сырым данным, чтобы новая метрика не начиналась с нуля |
| `cameras-combined.py` | Переводит SLA камер на все NVR: заполняет историю, меняет формулы calculated-items, перестраивает график на дашборде, удаляет лишние копии |

ID элементов данных (`itemid`, `hostid`) указаны для моей инсталляции. Перед запуском их нужно заменить на свои.

```bash
export ZABBIX_URL=https://zabbix.example.com/api_jsonrpc.php
export ZABBIX_TOKEN=...            # API-токен пользователя с правами на запись
python3 vpn-external-trigger.py
```

## Неочевидные особенности Zabbix API, на которые я наткнулся

- `history.push` пишет только в **trapper**-элементы. Для calculated и dependent он отвечает «Unsupported item type». Поэтому история заполняется через параллельный trapper-элемент, а на графике обе серии рисуются одним цветом.
- `history.push` **молча отбрасывает** значения старше периода хранения истории элемента и при этом сообщает 0 ошибок. Перед заполнением историю нужно увеличить.
- Источник для заполнения — **тренды** (почасовые min/avg/max хранятся 365 дней), потому что сырая история хранится всего 7 дней.
- У SLA `service_tags` оператор `2` (Like) молча ничего не находил. Оператор `0` (Equals) работает.
- `algorithm` у сервиса легко перепутать: `2` означает «худший из дочерних», `1` означает «проблема, только если упали все».
- `dashboard.create` сохраняет несуществующие поля виджета без ошибки, но виджет потом показывает «not fully configured». Поля проверяет фронтенд, а не API.
- Большие диапазоны `history.get` упираются в 504, поэтому скрипты запрашивают данные кусками по 2 дня.
